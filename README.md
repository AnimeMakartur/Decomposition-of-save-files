# Cities: Skylines II Save Data Exporter

Проєкт для вилучення даних із файлів збереження **Cities: Skylines II** та підготовки структурованого опису міста для подальшого аналізу за допомогою ШІ.

## Мета

Після вибору файлу збереження проєкт має:

1. Прочитати дані міста зі збереження.
2. Відібрати потрібну інформацію про дороги, зокрема їхні типи, зупинки громадського транспорту та будівлі.
3. Об'єднати пов'язані дані у зрозумілий структурований опис.
4. Передати цей опис ШІ для подальшого опрацювання — через зовнішній API або локальну модель.

Такий підхід має допомогти аналізувати інфраструктуру міста, знаходити зв'язки між дорогами, зупинками й будівлями та формулювати висновки у зручному для людини вигляді.

## Передбачуваний процес

```text
Файл збереження
       ↓
Читання та вилучення даних
       ↓
Нормалізація доріг, зупинок і будівель
       ↓
Структурований набір даних
       ↓
ШІ через API або локально
       ↓
Аналіз і зрозумілий результат
```

Формат експорту та спосіб інтеграції з моделлю ще потрібно визначити. Серед можливих форматів для обміну даними — JSON або CSV.

## Поточний стан

Мод експортує дані активного міста у JSON після завершення завантаження гри. Експорт містить вузли й сегменти доріг, смуги, будівлі, зупинки та лінії громадського транспорту.

Для ліній експортуються тип транспорту, послідовність розпізнаних зупинок, початкова й кінцева зупинки, доступні дорожні сегменти, ціна квитка з компонента гри та транспортні засоби з місткістю пасажирів. Місткість лінії — сума місткостей транспортних засобів, призначених лінії в момент експорту; якщо гра не надає місткість хоча б одного з них, загальне значення буде `null`. Аналогічно, зупинки, тип яких не визначається з даних префаба, матимуть тип `Unknown`.

Список `RoadEdgeIds` включає лише сегменти, які вдалося зіставити з дорожніми смугами збереженої маршрутної геометрії. Це не гарантує повноту для всіх режимів транспорту чи станів симуляції. Ціна квитка записується без перерахунку з поля гри.

## Оцінка пішої доступності

Координати будівель і зупинок у JSON — координати ігрового світу, а не географічні широта й довгота. Пряма відстань між ними дає лише відстань «по повітрю» і нижню межу для пішого маршруту. За нею можна оцінити орієнтовний час, поділивши відстань на обрану швидкість ходьби, але така оцінка не враховує квартали, переходи, доступ до входу, рельєф і відсутні або закриті тротуари.

Для практичної оцінки можна використовувати пряму відстань як швидкий фільтр найближчих зупинок. Для надійнішого часу прогулянки потрібен пошук маршруту по пішохідній мережі міста з урахуванням доступності переходів і входу до будівлі; саме координат недостатньо. Без такого графа точність часу може суттєво відрізнятися від фактичного, особливо в щільній забудові або біля води й автомагістралей.

## Інтеграція з ШІ

Передбачено два можливі способи обробки даних:

- **Через API** — передавати підготовлені дані сумісному з проєктом сервісу ШІ.
- **Локально** — обробляти дані локальною моделлю, щоб не надсилати їх зовнішньому сервісу.

Конкретну модель, API, формат запитів і спосіб запуску буде обрано під час реалізації. Для API-інтеграції ключі доступу потрібно зберігати поза вихідним кодом.
